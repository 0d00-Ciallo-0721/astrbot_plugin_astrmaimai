## 阻塞问题

### B1. `text_segmenter.py:241-244` — `semantic_chunk()` 正则中使用了错误的转义，永远无法匹配换行

```python
# 源代码第 241-244 行
text = re.sub(r'\\n(#+\\s+)', r'\\n\\n\1', text)      # ❌ 匹配的是文字 \n 而非换行符
raw_chunks = [c.strip() for c in re.split(r'\\n{2,}', text) if c.strip()]  # ❌ 同上
```

**问题**：Python 中 `r'\\n'` 是三个字符的字符串 `\`, `\`, `n`（因为 `\\` 是两个反斜线），传递给 `re` 模块后匹配的是**文字反斜线后跟字母 n**，而非换行符。实际应该使用 `r'\n'`（两个字符：`\`, `n`）让 `re` 模块正确解释为换行。

**影响**：`semantic_chunk()` 无人调用（当前是死方法），但若未来启用，双重换行切分逻辑会完全失效，且 Markdown 标题预处理也将失败。

**建议**：
```python
# 修复后
text = re.sub(r'\n(#+\s+)', r'\n\n\1', text)           # ✓ 匹配实际换行
raw_chunks = [c.strip() for c in re.split(r'\n{2,}', text) if c.strip()]  # ✓
```

注意：若意图匹配 `\n` 换行符本身（而非 `\r\n`），此修复是充分必要条件。

## 轻微问题

### N1. 多处 `except ImportError` fallback — 兼容性死代码

`executor.py:12-18`、`reply_artifact_builder.py:12-25` 均定义了运行时从不触发的回退类（如 `class Plain: ...`）。

```python
try:
    from astrbot.api.message_components import Plain
except ImportError:  # pragma: no cover
    class Plain:
        def __init__(self, text: str):
            self.text = text
```

这些回退类无法被类型检查器正确识别（`# type: ignore[override]`），且在 AstrBot 生产环境中该导入不可能失败。建议在代码库确认支持的 Python 最低版本后清理。

### N2. `cognitive_loop.py` — `_build_initial_prompt()` 在不支持 `get_extra` 的事件上使用空字符串作为 think_level

```python
# cognitive_loop.py:350-357
if hasattr(event, "get_extra"):
    ...
    think_level = event.get_extra("astrmai_think_level", "")
    think_reason = ...
    think_signals = ...
else:
    think_level = ""     # ← 空字符串，下方用于 f-string
    think_reason = ""
    think_signals = []
```

空字符串 `""` 作为 `think_level` 在拼入 prompt 时格式为 `level=`（无值），略显不规则。建议统一为 `"N/A"` 或 `"0"`。

### N3. `reply_artifact_builder.py` — `_at_component` 参数硬编码 `qq=` 属性名

```python
def _at_component(uid: Any):
    return _component_instance(Comp.At, uid, "qq", qq=uid)
```

`Comp.At` 的构造参数在不同 IM 协议适配器中可能不是 `qq`（如 Telegram 是 `user_id`）。当前仅限 QQ 协议场景，但代码结构缺少协议抽象层。建议在配置层做协议名称 → 参数名的映射。
