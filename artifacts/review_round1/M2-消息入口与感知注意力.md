## 阻塞（Blocking）

### B1. `compaction_providers.py` — `policy` 为 `None` 时访问 `policy.lane_key` 可能抛 `AttributeError`

- **文件**：`astrmai/conversation/attention/compaction_providers.py`, L85–86
- **问题**：`_compaction_provider_kwargs()` 方法中，`economy.resolve_policy(request)` 的类型标注为 `-> WorkloadPolicy`（非可选），但若 `economy` 内部表找不到匹配的 policy（例如 `pool_name="memory"` 但未注册），部分分支可能返回 `None`。当前代码直接访问 `policy.lane_key` / `policy.use_provider_session` 等属性，未先判空。
- **风险**：若调用时 `resolve_policy` 返回 `None`，此处抛 `AttributeError` 会穿透整个 `_build_summary_with_provider` / `_build_summary_with_provider_v2`，导致该 chat 的 compaction 静默失败（外层 try/except 捕获与否取决于调用栈）。
- **建议**：在 `policy = economy.resolve_policy(request)` 后立即判空：
  ```python
  if policy is None:
      return {}, {}
  ```

### B2. `gate.py` — `_is_direct_wakeup_event` 调用传感器方法未处理异常传播

- **文件**：`astrmai/conversation/attention/gate.py`, L144–147
- **问题**：`_is_direct_wakeup_event` 在 `try` 中调用 `self.sensors.is_wakeup_signal(event, self_id)`。虽然 `is_wakeup_signal` 本身是同步方法且不含复杂逻辑，但如果 `self.sensors` 为 `None`（`AttentionGate.__init__` 允许 `sensors=None`），此处会抛出 `AttributeError: 'NoneType' object has no attribute 'is_wakeup_signal'`，而不是优雅降级。
- **风险**：若 `AttentionGate` 被以 `sensors=None` 构造（例如测试环境），第一条消息到达 `process_event → _resolve_wakeup_flags → _is_direct_wakeup_event` 时会崩溃。
- **建议**：在调用前加 `self.sensors is not None and ` 守卫，或改为：
  ```python
  try:
      return bool(self.sensors is not None and self.sensors.is_wakeup_signal(event, self_id))
  except Exception:
      return False
  ```

## 应修复（Should-fix）

### S1. `sensors.py` — 文件头注释指向已删除的旧路径

- **文件**：`astrmai/conversation/ingress/sensors.py`, L1
- **问题**：注释写的是 `# astrmai/Heart/sensors.py`，但实际路径为 `astrmai/conversation/ingress/sensors.py`。该路径 `astrmai/Heart/` 已被重构删除，此注释在以后代码搜索时造成误导。
- **建议**：删除或更正为实际路径。

### S2. `sensors.py` — 方法内重复 `import re`

- **文件**：`astrmai/conversation/ingress/sensors.py`, L311（`should_process_message` 方法内）
- **问题**：方法内部有 `import re`（注释中也注明"如果文件顶部已经 import re，这里的可以删除"），而文件顶部第 4 行已经 `import re`。虽然不是运行时错误（Python 会复用已缓存模块），但会造成 LSP 误报和代码阅读困惑。
- **建议**：删除方法内的 `import re`。

### S3. `compaction_providers.py` — v1/v2 摘要构建的回退分支是不可达的死代码

- **文件**：`astrmai/conversation/attention/compaction_providers.py`, L125–136 和 L225–236
- **问题**：`_build_summary_with_provider` 和 `_build_summary_with_provider_v2` 中，`envelope` 通过以下方式赋值：
  ```python
  envelope = self._render_compaction_envelope(...) if hasattr(self, "_render_compaction_envelope") else None
  ```
  但 `_render_compaction_envelope` 是 `CompactionProviderMixin` 自身的实例方法，`hasattr(self, "_render_compaction_envelope")` 永远为 `True`。因此 `if envelope is not None` 分支总是走通，`else` 分支（手动设置 `template_id=PromptTemplateId.COMPACTION_SUMMARY_V1.value` 等的降级逻辑）永远不会执行。
- **影响**：低。若 `_render_compaction_envelope` 内部返回 `None`（当 `prompt_registry is None` 时），`envelope` 为 `None`，代码仍有降级能力。但 `hasattr` 守卫是多余且误导的。
- **建议**：删除 `hasattr` 守卫，直接调用 `self._render_compaction_envelope(…)`：
  ```python
  envelope = self._render_compaction_envelope(...)
  ```

## 建议（Nits）

### N1. `perception.py` — `PerceptionSnapshot` 在 `build()` 内和调用侧各设置了一次

- **文件**：`astrmai/conversation/attention/perception.py`, L53 / `astrmai/conversation/attention/gate.py`, L613
- **问题**：`PerceptionBuilder.build(event)` 方法内部已调用 `ensure_turn_context(event).perception = snapshot`；但在 `gate.py` 的 `process_event` 中，调用 `build()` 后又执行 `turn_context.perception = perception`。相当于 per-turn 的 perception 快照被写入了两次。
- **影响**：无功能性影响（第二次赋值覆盖相同对象引用），但属于冗余操作，且日后若 `build()` 内部逻辑变更而 `process_event` 未同步更新，可能引入隐蔽的不一致。
- **建议**：二者择一保留。推荐在 `build()` 内设置、`process_event` 中删除重复赋值。
