# M1 模块：插件入口与启动装配

## 范围
- `main.py`
- `config.py`
- `_conf_schema.json`
- `astrmai/app/`

## 结论
- 插件入口 `main.py` 当前仍然可加载，不存在我已确认的“入口即崩”问题。
- 本模块当前最明确的真实问题集中在**配置模型与 schema 的断裂**。
- 这些问题更准确地说是 **P1 / 高优先级配置断裂**，而不是“启动阻断”。

## Findings

### P1-1 `conversation` 配置段在 schema 存在，但在 Pydantic 模型中缺失
- 文件：
  - `_conf_schema.json:168`
  - `config.py:186` 附近的 `AstrMaiConfig`
  - `astrmai/app/bootstrap.py:208-240`
- 相关对象：
  - `_conf_schema.json` 中的 `conversation`
  - `AstrMaiConfig`
  - `bootstrap.py` 中通过 `getattr(runtime.config, "conversation", None)` 读取配置的逻辑
- 当前事实：
  - schema 中仍有 `conversation` 配置段
  - `AstrMaiConfig` 当前没有 `conversation` 字段
  - `bootstrap.py` 里仍在读取 `runtime.config.conversation`
- 触发条件：
  - 用户通过 schema / WebUI / 配置文件写入 `conversation.*`
- 影响：
  - 配置不会按预期进入 Pydantic 模型
  - 下游会静默回退到硬编码默认值
  - 不一定崩溃，但运行行为和用户配置不一致
- 建议修复方向：
  - 增加 `ConversationConfig`
  - 在 `AstrMaiConfig` 中补入 `conversation: ConversationConfig = Field(default_factory=ConversationConfig)`

### P1-2 `deep_temporal_*` / `maintenance_*` 的 schema 命名空间与代码模型不一致
- 文件：
  - `_conf_schema.json:42-82`
  - `config.py:140-148`
- 相关对象：
  - schema 中的 `global_settings.deep_temporal_*`
  - schema 中的 `global_settings.maintenance_*`
  - `MemoryConfig`
- 当前事实：
  - schema 仍把这些字段挂在 `global_settings`
  - `config.py` 仍把这些字段定义在 `MemoryConfig`
- 触发条件：
  - 用户通过配置界面修改这组参数
- 影响：
  - 代码读取 `config.memory.*` 时拿不到用户配置
  - 最终静默回退到默认值
- 建议修复方向：
  - 把 schema 中这组字段迁移到 `memory` 段
  - 或者反向调整代码模型，但两边必须统一

### P2-1 `performance` 在模型中存在，但 schema 中缺失
- 文件：
  - `config.py:34`
  - `config.py:186`
  - `_conf_schema.json`
- 相关对象：
  - `PerformanceConfig`
  - `AstrMaiConfig.performance`
- 当前事实：
  - `config.py` 中存在 `PerformanceConfig`
  - schema 中没有对应 `performance` 段
- 影响：
  - 用户无法通过配置入口调整该组参数
- 建议修复方向：
  - 在 schema 中补入 `performance` 段

### P2-2 `jargon_min_count` 在模型中存在，但 schema 中缺失
- 文件：
  - `config.py:90`
  - `astrmai/learning/review/jargon_auto_check_task.py:85-110`
  - `astrmai/learning/mining/jargon_miner.py:18`
  - `_conf_schema.json`
- 当前事实：
  - `EvolutionConfig` 中存在 `jargon_min_count`
  - 下游代码也在读取它
  - schema 中缺少该字段
- 影响：
  - 该参数只能走代码默认值，无法由用户配置
- 建议修复方向：
  - 在 schema 的 `evolution` 段补入 `jargon_min_count`

### P3-1 schema 文本存在明显乱码，不利于配置使用
- 文件：
  - `_conf_schema.json` 多处
  - `config.py` 多处说明文本
- 当前事实：
  - 描述文本已有明显 mojibake
- 影响：
  - AI 仍能读结构
  - 但人类在配置界面里会明显读不顺
- 建议修复方向：
  - 后续统一修正文案编码

## 修复优先级建议
1. 先修 `conversation` 配置断裂
2. 再修 `deep_temporal_*` / `maintenance_*` 错位
3. 再补 `performance` / `jargon_min_count`

## 备注
- 本模块当前没有被我复核出“主入口 main.py 自身不可加载”的证据。
- 真正的问题在于：配置层与运行层未对齐。
