# M1 模块：插件入口与启动装配

## 范围
- `main.py`
- `config.py`
- `_conf_schema.json`
- `astrmai/app/`

## 结论
- 插件入口 `main.py` 当前仍然可加载，不存在我已确认的“入口即崩”问题。
- 本模块此前最明确的真实问题集中在**配置模型与 schema 的断裂**。
- 其中 `conversation` 承接缺失、`deep_temporal_*` / `maintenance_*` 命名空间错位已完成修复。
- 当前剩余关注项主要是非本轮范围内的 schema 覆盖缺口与文案质量问题，而不是“启动阻断”。

## Findings

### Fixed-1 `conversation` 配置段已补齐真实模型承接
- 文件：
  - `_conf_schema.json`
  - `config.py`
  - `astrmai/app/bootstrap.py`
- 相关对象：
  - `_conf_schema.json` 中的 `conversation`
  - `AstrMaiConfig`
  - `bootstrap.py` 中通过 `getattr(runtime.config, "conversation", None)` 读取配置的逻辑
- 当前事实：
  - `config.py` 已新增 `ConversationConfig`
  - `AstrMaiConfig` 已正式承接 `conversation`
  - schema 与模型的默认值已统一到真实运行默认行为
- 修复结果：
  - `config.conversation.*` 可被真实解析并下传到 bootstrap / feature flags 链路
  - 不再依赖“模型字段不存在时”的静默默认值来维持运行

### Fixed-2 `deep_temporal_*` / `maintenance_*` 已统一到 `memory` 命名空间
- 文件：
  - `_conf_schema.json`
  - `config.py`
- 相关对象：
  - schema 中的 `memory.deep_temporal_*`
  - schema 中的 `memory.maintenance_*`
  - `MemoryConfig`
- 当前事实：
  - schema 已将这组字段迁移到 `memory`
  - `config.py` 继续由 `MemoryConfig` 统一承接
  - 对旧配置输入增加了只读归一化：`global_settings.*` 旧写法会迁移到 `memory.*`
- 修复结果：
  - 正式配置入口与运行时读取位一致
  - 新旧配置并存时以 `memory.*` 为准，避免覆盖新写法

### Fixed-3 `performance` 已补齐 schema 暴露并接入真实配置链
- 文件：
  - `config.py:34`
  - `config.py:186`
  - `_conf_schema.json`
- 相关对象：
  - `PerformanceConfig`
  - `AstrMaiConfig.performance`
- 当前事实：
  - `_conf_schema.json` 已新增顶层 `performance` 段
  - `summary_threshold` 默认值已与 `PerformanceConfig.summary_threshold = 300` 对齐
  - 插件入口与热应用入口都继续通过 `AstrMaiConfig(**data)` 解析该字段
- 修复结果：
  - `config.performance.summary_threshold` 现在可由正式配置入口写入
  - `PersonaSummarizer` 的阈值读取不再是模型-only 配置

### Fixed-4 `jargon_min_count` 已补齐 schema 暴露并与下游读取对齐
- 文件：
  - `config.py:90`
  - `astrmai/learning/review/jargon_auto_check_task.py:85-110`
  - `astrmai/learning/mining/jargon_miner.py:18`
  - `_conf_schema.json`
- 当前事实：
  - `_conf_schema.json` 的 `evolution` 段已补入 `jargon_min_count`
  - 默认值已与 `EvolutionConfig.jargon_min_count = 2` 对齐
  - `JargonMiner` 与 `JargonAutoCheckTask` 的读取路径继续保持 `config.evolution.jargon_min_count`
- 修复结果：
  - 该参数不再只能依赖代码默认值
  - `jargon_min_count` 已成为正式可配置参数，同时保留 `review_min_count` fallback 兼容逻辑

### P3-1 schema 文本存在明显乱码，不利于配置使用
- 文件：
  - `_conf_schema.json` 多处
  - `config.py` 多处说明文本
- 当前事实：
  - 描述文本已有明显 mojibake
- 影响：
  - AI 仍能读结构
  - 但人类在配置界面里会明显读不顺
- 建议修复方向：
  - 后续统一修正文案编码

## 修复优先级建议

2. 单独处理 schema 文案乱码
