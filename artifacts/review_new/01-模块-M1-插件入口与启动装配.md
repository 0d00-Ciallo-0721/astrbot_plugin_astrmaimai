# M1 模块：插件入口与启动装配

## 范围
- `main.py`
- `config.py`
- `_conf_schema.json`
- `astrmai/app/`

## 结论
- 插件入口 `main.py` 当前仍然可加载，不存在我已确认的“入口即崩”问题。
- 本模块此前最明确的真实问题集中在**配置模型与 schema 的断裂**。
- 其中 `conversation` 承接缺失、`deep_temporal_*` / `maintenance_*` 命名空间错位已完成修复。
- 当前剩余关注项主要是非本轮范围内的 schema 覆盖缺口与文案质量问题，而不是“启动阻断”。

## Findings

### Fixed-1 `conversation` 配置段已补齐真实模型承接
- 文件：
  - `_conf_schema.json`
  - `config.py`
  - `astrmai/app/bootstrap.py`
- 相关对象：
  - `_conf_schema.json` 中的 `conversation`
  - `AstrMaiConfig`
  - `bootstrap.py` 中通过 `getattr(runtime.config, "conversation", None)` 读取配置的逻辑
- 当前事实：
  - `config.py` 已新增 `ConversationConfig`
  - `AstrMaiConfig` 已正式承接 `conversation`
  - schema 与模型的默认值已统一到真实运行默认行为
- 修复结果：
  - `config.conversation.*` 可被真实解析并下传到 bootstrap / feature flags 链路
  - 不再依赖“模型字段不存在时”的静默默认值来维持运行

### Fixed-2 `deep_temporal_*` / `maintenance_*` 已统一到 `memory` 命名空间
- 文件：
  - `_conf_schema.json`
  - `config.py`
- 相关对象：
  - schema 中的 `memory.deep_temporal_*`
  - schema 中的 `memory.maintenance_*`
  - `MemoryConfig`
- 当前事实：
  - schema 已将这组字段迁移到 `memory`
  - `config.py` 继续由 `MemoryConfig` 统一承接
  - 对旧配置输入增加了只读归一化：`global_settings.*` 旧写法会迁移到 `memory.*`
- 修复结果：
  - 正式配置入口与运行时读取位一致
  - 新旧配置并存时以 `memory.*` 为准，避免覆盖新写法

### P2-1 `performance` 在模型中存在，但 schema 中缺失
- 文件：
  - `config.py:34`
  - `config.py:186`
  - `_conf_schema.json`
- 相关对象：
  - `PerformanceConfig`
  - `AstrMaiConfig.performance`
- 当前事实：
  - `config.py` 中存在 `PerformanceConfig`
  - schema 中没有对应 `performance` 段
- 影响：
  - 用户无法通过配置入口调整该组参数
- 建议修复方向：
  - 在 schema 中补入 `performance` 段

### P2-2 `jargon_min_count` 在模型中存在，但 schema 中缺失
- 文件：
  - `config.py:90`
  - `astrmai/learning/review/jargon_auto_check_task.py:85-110`
  - `astrmai/learning/mining/jargon_miner.py:18`
  - `_conf_schema.json`
- 当前事实：
  - `EvolutionConfig` 中存在 `jargon_min_count`
  - 下游代码也在读取它
  - schema 中缺少该字段
- 影响：
  - 该参数只能走代码默认值，无法由用户配置
- 建议修复方向：
  - 在 schema 的 `evolution` 段补入 `jargon_min_count`

### P3-1 schema 文本存在明显乱码，不利于配置使用
- 文件：
  - `_conf_schema.json` 多处
  - `config.py` 多处说明文本
- 当前事实：
  - 描述文本已有明显 mojibake
- 影响：
  - AI 仍能读结构
  - 但人类在配置界面里会明显读不顺
- 建议修复方向：
  - 后续统一修正文案编码

## 修复优先级建议
1. 继续补 `performance` 的 schema 暴露
2. 继续补 `jargon_min_count` 的 schema 暴露
3. 后续单独处理 schema 文案乱码

## 备注
- 本模块当前没有被我复核出“主入口 main.py 自身不可加载”的证据。
- 本轮已完成配置层与运行层的核心对齐，剩余问题不在本次修复范围。
