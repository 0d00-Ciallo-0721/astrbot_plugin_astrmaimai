# Prompt 13：剩余收尾与宿主级验收

## 任务目标
在前 01-12 已完成的基础上，做最后一轮“小范围高价值收尾”，把当前仓库仍未彻底清零的内容压缩到最小，并补一份更接近真实发布前验收的结论。

1. `EvolutionManager` sync/async 兼容边界最终收口

3. 做一次更接近真实宿主环境的主链/页面/API 最小验收

## 必须完成的工作

### 1. 收口 EvolutionManager 最后一层兼容边界
- 继续搜索仓内生产调用点，确认是否仍有异步上下文误用：
  - `get_active_patterns()`
  - `get_active_patterns_canonical()`
- 如果还有生产链误用，改成正式 async API。
- 如果当前只剩兼容包装，明确其定位：
  - 仅兼容同步上下文
  - 不再让真实主链依赖它
- 补一条小回归，锁死“异步上下文不得再走同步包装”。

### 2. 对配置链做覆盖性复查
- 不是重复修已经关闭的 4 个缺口。
- 而是以 `AstrMaiConfig` 为源，系统检查：
  - 模型里有但 schema 未暴露
  - schema 暴露了但运行时未消费
  - 关键默认值是否仍然对齐
- 优先覆盖这些配置段：
  - `performance`
  - `evolution`
  - `conversation`
  - `memory`
  - `vision`
  - `private_chat`
- 如果没有发现新的真实断裂，要把这个结论写清楚，不要继续保守地泛写“建议复查”。

### 3. 做一次最小宿主级验收
- 目标不是重建整套大型 E2E。
- 目标是让“当前大概率可加载、主链大概率可用”升级为“已有更实的宿主级证据”。
- 至少覆盖：
  - 插件注册/加载
  - `main.py -> PluginFacade.on_global_message() -> yield reply`
  - Plugin Page 主入口可注册
  - 关键 backend API 不因前期删 frontend / mock / standalone 残留而断裂

## 实施要求
- 不要在本轮重新打开已经明确收口的问题。
- 不要顺手扩大为新一轮大重构。
- 若配置链复查后确认“定义层已经收完，只剩文档口径过保守”，优先同步修正文档结论，而不是人为制造新待办。
