# M2 模块：消息入口与感知/注意力

## 范围
- `astrmai/conversation/ingress/`
- `astrmai/conversation/attention/`

## 结论
- ingress -> attention 主数据链没有被我复核出明确断链。
- 但当前仍存在两类真实风险：
  - 空值/依赖防护不足
  - 少量维护性残留

## Findings

### P1-1 `compaction_providers.py` 对 `resolve_policy()` 的结果缺少显式空值防护
- 文件：
  - `astrmai/conversation/attention/compaction_providers.py:77-90`
- 相关函数：
  - `_compaction_provider_kwargs(...)`
- 当前事实：
  - `policy = economy.resolve_policy(request)`
  - 随后直接访问 `policy.lane_key`
  - 当前代码里没有 `policy is None` 判断
- 触发条件：
  - 若 `resolve_policy(...)` 在某些边界条件下返回 `None`
- 影响：
  - 会导致 `AttributeError`
  - 更偏向“条件触发型运行时风险”
- 建议修复方向：
  - 对 `policy` 加显式判空
  - 或让 `resolve_policy` 的返回约束更明确

### P1-2 `gate.py` 对 `self.sensors` 的依赖防护不足
- 文件：
  - `astrmai/conversation/attention/gate.py:137`
- 相关函数：
  - `_is_direct_wakeup_event(...)`
- 当前事实：
  - 该函数会调用 `self.sensors.is_wakeup_signal(...)`
  - 虽然有异常兜底，但代码对 `sensors=None` 的语义并不清晰
- 触发条件：
  - 测试环境或特殊构造路径下 `sensors` 缺失
- 影响：
  - 可能转化为异常降级路径
  - 行为不够稳定、难排查
- 建议修复方向：
  - 显式判断 `self.sensors is not None`
  - 把该依赖做成更清晰的可选/必选契约

### P2-1 `sensors.py` 顶部旧路径注释残留
- 文件：
  - `astrmai/conversation/ingress/sensors.py:1`
- 当前事实：
  - 顶部仍残留旧路径注释语义
- 影响：
  - 不影响运行
  - 会误导维护者
- 建议修复方向：
  - 清理或改正注释

### P2-2 `sensors.py` 存在方法内重复导入
- 文件：
  - `astrmai/conversation/ingress/sensors.py`
- 当前事实：
  - 文件顶部已 `import re`
  - 方法内又有重复导入痕迹
- 影响：
  - 不影响运行
  - 可读性差
- 建议修复方向：
  - 清理重复导入

### P2-3 `PerceptionSnapshot` / `gate` 之间存在重复赋值痕迹
- 文件：
  - `astrmai/conversation/attention/perception.py`
  - `astrmai/conversation/attention/gate.py`
- 当前事实：
  - `PerceptionBuilder.build()` 内部会写入 turn context
  - `gate` 侧仍有重复赋值模式
- 影响：
  - 当前更像冗余逻辑
  - 未来易造成维护分叉
- 建议修复方向：
  - 保留一个权威写入点

## 修复优先级建议
1. 先补 `policy` 判空
2. 再补 `sensors` 显式守卫
3. 最后清理注释/重复导入/重复赋值
