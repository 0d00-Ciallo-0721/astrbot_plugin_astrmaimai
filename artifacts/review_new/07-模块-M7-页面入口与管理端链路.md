# M7 审查报告：页面入口与管理端链路

## 说明
- 本报告已按当前仓库代码重新校正。
- 仅修正结论口径，不修改业务代码。
- 旧版报告中“整体 Web 管理链不可发布”的说法需要收窄影响面。

## 当前有效的核心结论

### 1. standalone FastAPI backend 的 route/service 显性断裂已收口
本轮已完成的修复：

- `astrmai/webui/backend/routes/cognition_routes.py`
- `astrmai/webui/backend/routes/runtime_routes.py`
- `astrmai/webui/backend/routes/heartflow_routes.py`
- `astrmai/webui/backend/routes/learning_routes.py`
- `astrmai/webui/backend/routes/tools_routes.py`
  - 这 5 个 route 的 `_service()` 已不再把 `get_db` 多传给只接收 `plugin_api` 的 service
  - `LearningService`、`ToolsService`、`CognitionService` 已补齐 route 当前真实使用的方法委托与签名
  - 对应 service 的真实构造依赖现已统一回到单参数 `plugin_api`
  - 结合 backend route 相关测试与最小路由调用复核，当前未再复现这组“route 直接调用不存在方法 / 签名不兼容方法”的显性断裂

### 2. Plugin Page 主入口不能和 standalone FastAPI 混为一谈
当前项目里真实存在两种不同入口理解：

- AstrBot Plugin Page 主入口
  - `main.py`
  - `astrmai/webui/plugin_pages.py`
- standalone FastAPI backend
  - `astrmai/webui/backend/server.py`
  - `astrmai/webui/backend/routes.py`

当前更准确的判断是：
- **此前确认的 standalone FastAPI backend route/service 断裂已收口**
- **AstrBot Plugin Page 主入口不应直接被上述 route/service 断裂等同判死**
- `astrmai/webui/backend/server.py` 运行时导入的 `astrmai.webui.backend.routes` 实际解析到 `routes/__init__.py`；同级 `backend/routes.py` 当前不是运行时主入口，不应与包入口并列视为同等真相来源

## 修正后的影响判断

### 仍然可以保留的结论
- M7 曾经存在一组真实运行级断裂
- Plugin Page 主入口与 standalone FastAPI backend 应分开判断

### 需要删掉或收窄的结论
- 不应直接写成“当前整个页面入口与管理端链路都不可发布”
- 更准确的说法应为：
  - `Plugin Page` 主桥接链不等于 standalone FastAPI backend 链
  - 之前确认的 backend route/service 断裂已修复，但这不自动等同于“整个管理端已做完发布级验证”

## 当前建议优先级

### P1
- 若还要继续评估 M7，应补做更完整的 standalone backend 真机链路验证
- 至少保留一组真实 FastAPI 请求级 smoke，覆盖 `/api/tools/recent-calls`、`/api/cognition/chats/{chat_id}/unified-timeline`、`/api/cognition/observability/overview`、`/api/cognition/scheduler/status`、`/api/learning/reflect/run-once`
- 将后续重点转回其余仍未关闭的全局问题，而不是重复处理已收口的 route/service 断裂

### P2
- 再重新区分哪些 backend route 真正仍需要保留
- 避免仓库里继续存在“主链路不走、但代码还挂着”的服务端残留

## 结论
- 旧版 M7 的问题本体不是错的
- 但旧版把影响面说大了
- 现在应将 M7 解释为：
  - 此前确认的 `standalone FastAPI backend` route/service 断裂已收口
  - `Plugin Page` 主入口不应直接被一并判死
