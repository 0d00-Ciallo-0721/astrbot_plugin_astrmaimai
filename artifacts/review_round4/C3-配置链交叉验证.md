# C3 配置链交叉验证：M1 阻断问题追踪

## 验证结论

| 问题 | 严重性 | 是否导致启动崩溃 | 影响 |
|------|--------|-----------------|------|
| B1: `conversation` 在 Pydantic 模型中缺失 | **Should-fix** | ❌ 否 | 用户配置静默丢失，全部回退硬编码默认值 |
| B2: `deep_temporal_*`/`maintenance_*` 位置错位 | **Should-fix** | ❌ 否 | 用户配置静默丢失，全部回退 `MemoryScoringConfig` 默认值 |

**总体判断：不会导致插件启动崩溃，但所有用户对这两组参数的手动配置均被静默吞没。**

## B1: `conversation` 段追踪

### 断裂位置

- `_conf_schema.json` 定义了完整的 `"conversation"` 段（11 个字段含默认值）
- `config.py` `AstrMaiConfig` 模型 **完全没有** `conversation: ConversationConfig` 字段
- 所有下游读取走的都是 `getattr(config, "conversation", None)` → `None` → 硬编码 fallback

### 下游全量受影响的读取点

| 位置 | 代码 | 读取的字段 | 缺失后果 |
|------|------|-----------|---------|
| `defaults.py:63` | `getattr(getattr(config, "conversation", None), "enable_dialogue_store", True)` | `enable_dialogue_store` | 默认 True，功能开启但用户无法关闭 |
| `defaults.py:64` | 同上 | `enable_context_compaction` | 默认 True |
| `defaults.py:65` | 同上 | `enable_prefix_caching` | 默认 True |
| `bootstrap.py:98` | `getattr(conversation_settings, "hot_zone_ttl_seconds", 30.0)` | `hot_zone_ttl_seconds` | 固定 30.0s，用户调不了 |
| `bootstrap.py:99` | `getattr(conversation_settings, "warm_zone_ttl_seconds", 300.0)` | `warm_zone_ttl_seconds` | 固定 300.0s |
| `bootstrap.py:100` | `getattr(conversation_settings, "warm_zone_max_tokens", 1200)` | `warm_zone_max_tokens` | 固定 1200 |
| `bootstrap.py:124` | `getattr(conversation_settings, "compaction_trigger_segments", 40)` | `compaction_trigger_segments` | 固定 40（且与 schema 默认值 30 不一致） |
| `bootstrap.py:125` | `getattr(conversation_settings, "compaction_trigger_tokens", 1800)` | `compaction_trigger_tokens` | 固定 1800 |
| `bootstrap.py:126` | `getattr(conversation_settings, "compaction_keep_recent_segments", 16)` | `compaction_keep_recent_segments` | 固定 16（与 schema 默认 12 不一致） |
| `bootstrap.py:127` | `getattr(conversation_settings, "compaction_summary_max_tokens", 450)` | `compaction_summary_max_tokens` | 固定 450 |
| `bootstrap.py:128` | `getattr(conversation_settings, "compaction_provider_id", "")` | `compaction_provider_id` | 固定空字符串 |
| `context_engine.py:30` | `getattr(getattr(self.config, "conversation", None), "enable_prefix_caching", True)` | `enable_prefix_caching` | 固定 True |
| `planner.py:102` | `getattr(getattr(gateway.config, "conversation", None), "enable_prefix_caching", True)` | `enable_prefix_caching` | 同上 |

### 为什么不会崩溃

所有读取点均使用 **双层 `getattr(obj, attr, default)`** 模式：
```
getattr(getattr(config, "conversation", None), "some_field", default)
```

外层返回 `None`，内层对 `None` 调用 `getattr` 返回 `default`。**没有 `AttributeError`，没有 `TypeError`。** 等价于完全忽略用户配置。

### 次级发现：Bootstrap 内默认值与 Schema 默认值不一致

| 字段 | Schema 默认值 | Bootstrap 硬编码默认值 |
|------|--------------|----------------------|
| `compaction_trigger_segments` | 30 | **40** |
| `compaction_keep_recent_segments` | 12 | **16** |
| `compaction_summary_max_tokens` | 450 | 450 ✅ |

即使 B1 修复后，仍需对齐这两处分歧。

## B2: `deep_temporal_*` / `maintenance_*` 位置错位

### 断裂位置

- `_conf_schema.json`：这些字段在 `"global_settings"` 段内
- `config.py` Pydantic 模型：这些字段在 `MemoryConfig` 下（挂载于 `config.memory.*`）
- 运行时消费代码：`memory_scoring.py` 的 `scoring_from_config()` 从 `config.memory.*` 读取

### 配置流向图

```
Schema: global_settings.deep_temporal_alpha  ──→  ??? 
                                                    ↓
Pydantic: AstrMaiConfig.memory.deep_temporal_alpha   ←── 运行时实际读取位置
                                                    ↓
MemoryScoringConfig.deep_temporal_alpha = 0.7  ←── 用户配置触达不到，永远用默认值
```

### 下游全量受影响的读取点

| 位置 | 读取方式 | 影响的运行时行为 |
|------|---------|----------------|
| `memory_scoring.py:133` | `scoring_from_config(config)` → `getattr(config, "memory", None)` | 全部 9 个 `deep_temporal_*`/`maintenance_*` 字段 |
| `memory_retrieval_service.py:39` | `scoring_from_config(getattr(engine, "config", None))` | `retrieve_deep()` 的候选池大小、LLM 窗口、时序重排序 |
| `memory_maintenance_service.py:11` | `scoring_from_config(config)` | `run_once()` 的 hot-score 阈值判定 |
| `memory_scoring.py:62` | `compute_temporal_boost()` → `scoring.deep_temporal_alpha/tau/lambda` | 记忆检索的时序保底分数 |
| `memory_scoring.py:84` | `compute_hot_score()` → `scoring.maintenance_hot_beta` | 维护服务的 stale 标记热力阈值 |
| `memory_maintenance_service.py:88` | `self.scoring.maintenance_temporal_stale_hot_threshold` | 扫描 `active` 记忆并标记 `stale` 的临界值 |

### 为什么不会崩溃

`scoring_from_config()` 在 `config.memory` 上找不到这些字段时，**静默返回 `MemoryScoringConfig()` 全默认实例**，不会抛出异常。`compute_temporal_boost()` 和 `compute_hot_score()` 均对 `None` 和 `0.0` 做 `min(max(...))` 夹紧防护。

## 联合影响评估

### 运行时行为变体矩阵

```
                用户配置了 B1+B2 相关字段      用户未配置（用默认值）
                ───────────────────────        ─────────────────
Bootstrap 启动        正常启动                       正常启动
对话存储（dialogue store） 用代码默认值                   用代码默认值（同左）
上下文压缩                  用代码默认值                    用代码默认值（同左）
前缀缓存                    用代码默认值                    用代码默认值（同左）
深度记忆检索                 用 MemoryScoringConfig 默认值      用 MemoryScoringConfig 默认值（同左）
记忆维护                    用 MemoryScoringConfig 默认值      用 MemoryScoringConfig 默认值（同左）
```

### 最坏场景

用户通过 WebUI 或手动编辑仔细调优了：
- `compaction_trigger_segments` = 100（减少压缩频率）
- `deep_temporal_alpha` = 0.3（降低时序权重）
- `maintenance_temporal_stale_hot_threshold` = 0.6（减少误标记）

但所有这些配置**全部被忽略**，系统按硬编码默认值运行。用户无法通过任何界面感知到配置没有生效——没有日志警告，没有异常，没有降级标记。

## 修复建议

### B1 修复方案

在 `config.py` 中新增 `ConversationConfig`：

```python
class ConversationConfig(BaseModel):
    enable_dialogue_store: bool = True
    enable_context_compaction: bool = True
    enable_prefix_caching: bool = True
    hot_zone_ttl_seconds: float = 30.0
    warm_zone_ttl_seconds: float = 300.0
    warm_zone_max_tokens: int = 1200
    compaction_provider_id: str = ""
    compaction_trigger_segments: int = 30   # 与 schema 对齐
    compaction_trigger_tokens: int = 1800
    compaction_keep_recent_segments: int = 12  # 与 schema 对齐
    compaction_summary_max_tokens: int = 450
```

并在 `AstrMaiConfig` 中增加 `conversation: ConversationConfig = Field(default_factory=ConversationConfig)`。

### B2 修复方案

方案 A（推荐）：将 `_conf_schema.json` 中的 `deep_temporal_*`/`maintenance_*` 从 `global_settings` 迁移到 `memory` 段，与 Pydantic 模型和运行时读取位置对齐。

方案 B：在 `scoring_from_config()` 中增加从 `config.global_settings` 的备选读取路径，兼容 schema 定义的两种位置。但此方案会永久遗留两套路径，增加维护成本。

---

## 验证方法

修复后可通过以下方式验证配置链正确性：

1. 启动日志 grep：`grep -i "conversation\|deep_temporal\|maintenance"` 确认日志或调试输出中包含用户配置值
2. 单元测试断言：`AstrMaiConfig(conversation={"compaction_trigger_segments": 100}).conversation.compaction_trigger_segments == 100`
3. 集成测试注入：通过 `raw_config` 传入完整配置后，确认 `build_infrastructure_settings()` 输出的 `RuntimeFeatureFlags.dialogue_store_enabled` 使用用户配置值而非默认值
