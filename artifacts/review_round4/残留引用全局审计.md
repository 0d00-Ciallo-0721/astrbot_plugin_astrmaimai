## 二、生产代码中真正需要处理的 🟡 问题

### 2.1 🟡 死代码：`IngressDecision` 双副本

**文件：** `astrmai/conversation/contracts/message_scope.py:10-26`

该文件包含与 `astrmai/presentation/dto/message_scope.py:10-26` **完全相同的 `IngressDecision` 和 `MessageScope` 类定义**。

**证据：** 全代码库搜索 `from astrmai.conversation.contracts.message_scope import` 返回 **0 条结果**。该文件无任何消费者，属于重构残留的副本。

**风险：**
- 如果未来有人误从此处 import，会得到与预期不同的模块（`presentation/dto/` 中的才是规范定义）
- 维护两份相同代码，修改时如果不记得删另一个，会导致行为差异

**建议：** 删除 `astrmai/conversation/contracts/message_scope.py`。

### 2.2 🟡 乱码日志：handoff_registry.py 的 mojibake

**文件：** `astrmai/workmode/tools/handoff_registry.py` 第 22、28、31、33 行

中文日志字符串以 UTF-8 字节被错误解码为 Latin-1，呈现为乱码（如 `鈿狅笍`、`鏈壘鍒?`、`馃攲` 等）。

**影响：** 不影响运行时逻辑，但日志输出不可读，对调试和监控有影响。

**建议：** 将相关字符串重新保存为正确的 UTF-8 编码。

### 3.2 已迁移测试文件 —— `sys.modules.pop()` 清理旧缓存

50+ 个测试文件（分布在 `tests/`、`tests/original_ported/`、`tests/unit/`、`tests/integration/`、`tests/regression/` 下）执行类似：

```python

```

这些是 `pop(key, None)` 调用，**不会崩溃**，只是在 import 新路径前清除 Python 模块缓存中的旧条目。属于迁移过程中的安全保护措施。

### 3.3 架构回归测试 —— 声明式禁止列表

`tests/regression/architecture/test_import_boundaries_refactor.py:101-103` 中定义了：

```python
forbidden_prefixes = (
    "astrmai.Brain",
    "astrmai.Heart",
    "astrmai.infra",

```

这是**正确**的——该测试确保迁移后的新测试不会意外依赖旧命名空间。它是防止退化的一线防御。
