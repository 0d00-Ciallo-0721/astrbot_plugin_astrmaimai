## 🔴 Blocking

### B1. `cognition_routes.py` 与 `CognitionService` 构造函数签名不匹配 (运行时崩溃)

**文件**: `astrmai/webui/backend/routes/cognition_routes.py:11`, `cognitionservice.py:7`

**问题**: route 的 `_service()` 工厂调用 `CognitionService(PluginApiAdapter(), get_db)`，传递了两个位置参数；但 `CognitionService.__init__` 只接受 `plugin_api: PluginApiAdapter` 一个参数。

```
# routes/cognition_routes.py L11
def _service() -> CognitionService:
    return CognitionService(PluginApiAdapter(), get_db)   # TypeError!

# services/cognitionservice.py L7
class CognitionService:
    def __init__(self, plugin_api: PluginApiAdapter):     # 只接受 1 个参数
```

**影响**: 任何对 `/cognition/*` 系列 API 的请求都会立即崩溃，因为 FastAPI 在 handler 执行前调用 `_service()` 构造依赖时就会抛 `TypeError`。

**修复**: 移除 `get_db` 参数；或为 `CognitionService.__init__` 添加 `db_factory` 形参。

### B3. `CognitionService.cognition_unified_timeline` 签名不匹配

**文件**: `astrmai/webui/backend/routes/cognition_routes.py:56-62`, `services/cognitionservice.py:28`

**问题**: route 传递了 `limit`, `level`, `include` 三个关键字参数给 `cognition_unified_timeline()`，但该方法的定义为 `async def cognition_unified_timeline(self, chat_id: str) -> dict[str, Any]`——只接受 `chat_id`。

```
# 路由传入:
return await _service().cognition_unified_timeline(
    chat_id=chat_id,
    limit=limit,       # ❌ unexpected
    level=level,       # ❌ unexpected
    include=include_values,  # ❌ unexpected
)

# 方法签名:
async def cognition_unified_timeline(self, chat_id: str) -> dict[str, Any]:
```

**影响**: 只要请求 `GET /cognition/chats/{chat_id}/unified-timeline`，就会抛出 `TypeError: got unexpected keyword arguments`。

**修复**: 在 `CognitionService` 的该方法中添加 `limit`, `level`, `include` 参数，或直接传递到 `AdminUiService.cognition_unified_timeline`。

### B5. 多个 route 的 `_service()` 工厂传递了多余的 `get_db` 参数

**文件**:

### S3. `AdminUiService` 的嵌套 import 模式容易引发循环依赖

**文件**: `astrmai/webui/backend/services/admin_ui_service.py:18-26`

**问题**: `AdminUiService.__init__` 在方法体内部 import 了多个 service 模块（`ObservabilityService`, `HeartflowService` 等）。虽然这是延迟 import 避免循环依赖的常规做法，但有四点风险：

1. 如果被 import 的模块本身也依赖 `AdminUiService`，将形成运行时循环
2. import 错误只会在首次构造时暴露，无法在模块加载时检测
3. `from .observabilityservice import ObservabilityService` 中的文件名 `observabilityservice.py` 拼写不一致（其他文件是 snake_case，如 `cognitionservice.py`、`heartflowservice.py`）
4. `ObservabilityService` 构造时又反向 import `AdminUiService`——形成双向依赖

**影响**: 虽然没有即时代码错误，但这种循环依赖导致两个服务相互引用，增加维护成本。

**修复**: 将公共接口提取到独立的 `protocol.py` 或改用依赖注入方式解耦。

## ⚪ Nits

### N1. `app.js` 中 `normalizeTabId("settings")` 回退到 `"dashboard"`

**文件**: `pages/admin/app.js:14`

**问题**: TABS 数组中没有 `"settings"` 和 `"persona"` tab，但 `normalizeTabId` 将 `"settings"` 映射到 `"dashboard"`，将 `"persona"` 映射到 `"personaSlices"`。如果用户直接访问 `#settings` hash，它仅显示 dashboard 内容——这不太可能是有意行为。要么在 TABS 中添加一个 settings 页面，要么删除回退映射。

**影响**: 前端 hash 路由 `#settings` 静默回退到 Dashboard，用户可能困惑。

---

### N2. `plugin_pages.py` 中 `#memory-feedback` 描述含有乱码

**文件**: `astrmai/webui/plugin_pages.py:633-635`

**问题**: 三条 memory-feedback 路径的描述含有乱码文本：
```
"AstrMai 璁板繂鍙嶉"        → 应为 "记忆反馈"
"AstrMai 璁板繂鍙嶉鏉ユ簮" → 应为 "记忆反馈来源"
"AstrMai 绂佺敤璁板繂鍙嶉" → 应为 "禁用记忆反馈"
```

描述文本文件编码被错误解读为 Latin-1 导致。虽然描述不影响运行时，但在日志和调试时难以辨认。

**修复**: 将这些字符串替换为正确的 UTF-8 中文文本。
