## 应修复问题

### S1 — 非标准 stub 导入路径

`test_cognitive_loop_refactor.py:16`:
```python
from tests.original_ported.helpers import _install_astrbot_stubs
```
而该项目所有其他 `_refactor` 测试使用：
```python
from tests.helpers.astrbot_stubs import install_astrbot_stubs
```
两者功能相同（后者委托前者），但路径不一致。如果重构 `tests.original_ported.helpers`，`test_cognitive_loop_refactor.py` 会孤悬在外。

**建议**：统一为 `from tests.helpers.astrbot_stubs import install_astrbot_stubs`，删除 `tests/original_ported/helpers.py` 中的转发层。

### S2 — `test_config_standalone_refactor.py` 无 stub 保护

`tests/test_config_standalone_refactor.py:5`:
```python
from config import AstrMaiConfig
```
该文件未调用 `install_astrbot_stubs()`，当前能工作是因为 `config.py` 不依赖 `astrbot` 模块。但 `config.py` 如果将来引用 `astrbot` 类型或依赖，该测试会失败且无明确线索。

**建议**：在 `setUp` 中添加 `install_astrbot_stubs()`，或至少在文件注释中说明为何可以不用。

### S3 — 没有完整消息链路集成测试

当前测试按组件隔离验证：
- `test_attention_gate_refactor.py` → 注意力门
- `test_planner_cognitive_loop_refactor.py` → 规划器
- `test_executor_refactor.py` → 执行器
- `test_chat_loop_kernel_refactor.py` → 循环内核

但**没有一条测试**走通完整链路：`message_entry -> attention_gate -> planner -> executor -> reply`。

`tests/integration/host/test_host_mock_validation.py` 的 `test_message_entry_and_command_paths_work_with_mock_events` 最接近，但它也没有验证完整链路——它只确认了 `handle_global_message` 可调用和命令模块可导入。

**建议**：添加一个集成测试，真实调用 `handle_global_message` → `PluginFacade.record_and_dispatch_attention` → `AttentionGate.process_event` → `Planner.plan_and_execute` → `ConcurrentExecutor.execute`，验证消息走完全程且最终可通过 `reply_service.handle_reply` 发送。

### S4 — `_FakeEvent` 类定义重复且可能过时

至少 7 个测试文件各自定义了自己的 `_FakeEvent` 类，每个实现的接口子集不同：

| 文件 | `set_extra` | `get_extra` | `plain_result` | `message_obj` 类型 |
|------|-------------|-------------|----------------|-------------------|
| `test_chat_loop_kernel_refactor.py` | ✅ | ✅ | ✅ | `SimpleNamespace` |
| `test_cognitive_loop_refactor.py` | ✅ | ✅ | ❌ | `None` |
| `test_cognitive_feedback_refactor.py` | ✅ | ✅ | ❌ | `None` |
| `test_attention_gate_refactor.py` | ✅ | ✅ | ❌ | `SimpleNamespace` |
| `test_executor_refactor.py` | ✅ | ✅ | ❌ | `None` |
| `test_planner_cognitive_loop_refactor.py` | ✅ | ✅ | ❌ | `None` |
| `test_reverse_session_hook_refactor.py` | ✅ | ✅ | ❌ | `None` |

`AstrMessageEvent` 的真实接口可能增加方法或变更属性，这些 Fake 不会失效——测试会绿，但真实运行可能因缺少必要属性而失败。

**建议**：将 `_FakeEvent` 提取为共享 fixture（如 `tests/fixtures/fake_event.py`），并保持与 `AstrMessageEvent` 的同步。

## 建议优化（Nits）

### N1 — `conftest.py` 仅设置 `sys.path`，不提供 fixture

`tests/conftest.py` 只做：
```python
if str(_project_root) not in sys.path:
    sys.path.insert(0, str(_project_root))
```
没有提供任何 pytest fixture。所有测试都自行管理 `tempfile.TemporaryDirectory` + `install_astrbot_stubs()` + `importlib.reload()`。`setUp/tearDown` 代码在每个测试文件中重复，没有共享抽象。

**建议**：在 `conftest.py` 中添加一个 `astrbot_env` 范围为一组的 fixture，自动创建临时目录、安装 stub、并在拆卸时清理。当前模式是 `setUp/tearDown` 代码的模板复制。

### N2 — `_conf_schema.json` 测试正确但脆弱

`test_config_standalone_refactor.py:22-27` 硬编码了字段名 `use_native_main_reply_vision` 和 `native_main_reply_failure_cooldown_sec`。当前已通过验证（`vision` 节存在这些字段），但如果 schema key 改名，测试不会提前告警，因为测试硬编码了旧 key。

**建议**：改为从 `AstrMaiConfig` 模型通过 `.model_json_schema()` 导出 schema 并与 JSON 文件对比，或至少添加注释说明维护方式。

### N3 — `test_main_reverse_session_hook_refactor.py` 跳过 `__init__`

`test_main_reverse_session_hook_refactor.py:150`:
```python
plugin = object.__new__(self.main_mod.AstrMaiPlugin)
```
然后手动设置 `plugin.context`、`plugin.facade` 等。这意味着构造函数 `__init__` 中的任何逻辑（`PluginFacade` 装配、`register_astrmai_admin_pages`、`_apply_runtime_compat`）均未执行。

**建议**：如果构造函数副作用过多难以在测试中执行，至少验证 `__init__` 在 stub 环境下能完整跑完。
