## 10. 异常与瓶颈

### 延迟
- **judge 阶段是最大延迟源**: 同一会话内每轮多次 judge 调用，单次 3-16s
- query_rewrite 与 task 池偶发极端延迟 (70s+)，但调用频率低
- dialog 池延迟为 0ms (全缓存命中)，性能优秀

### 模型重试/超时
- Docker 日志中未检测到 provider_failure
- 未出现 GatewayUsage 级别的 retry 标记
- 有 1 次 ActionFailed (QQ 图片发送超时，非 LLM 问题)

### 缓存策略
- mood 池缓存命中率 38-84%，judge 池仅 0-25%
- **judge 缓存命中率偏低** — prompt hash 经常变动，说明上下文窗口内容变化频繁
- dialog 池缓存命中率 77-93%，说明 persona/system prompt 稳定性好

## 11. 优化建议

| 优先级 | 建议 | 原因 |
|--------|------|------|
| **P0** | 降低 judge 重复调用 | 同一轮内多次 judge（同 conversation_id），可通过 conversation 级缓存减少 |
| **P1** | 优化 judge prompt 稳定性 | prompt_hash 频繁变动导致 cache miss (0-25%) |
| **P1** | 审查 `skipped_wait` 策略 | 47% 消息被跳过，是否存在过度保守 |
| **P2** | query_rewrite/task 超时控制 | 偶发 70s+ 极端延迟 |
| **P2** | 群聊 1048356445 几乎不回复 | 1/50 回复率远低于其他群，检查配置 |
| **P3** | 记忆注入率偏低 | 仅 7.9%，活跃群聊完全无记忆 |
